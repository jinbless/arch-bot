# b-box(위반 위치 표시) 실측 프로브 — 2026-07-30

> **결론 선요약**: 위반 위치 b-box는 실 서비스에 **사용 가능** — 단 방식이 갈린다.
> ① 열린 탐색("위반을 찾아라") = 모델별 편차 크고 핵심 위반 누락 빈발. ② SSOT 구조도 체크리스트 주입 = **실패**(오히려 검출 감소 — arm C와 같은 패턴 3번째 재현). ③ **targeted grounding(조문 확정 후 "위치만" 질의) = 성공** — 정식 gpt-5.5 포함 3개 모델이 3/3 정확.
> **적용 여부 결정은 2차 검수 완료 후 재논의**(보류 중). 프로토타입 = `serving-team/08-app/backend/scripts/bbox_targeted_probe.py`.

## 배경
사용자 질문: 사진의 위반(고정식 사다리 제24조, 폐기물 제4조 등)을 b-box로 표기할 수 있나, GPT가 지원하나.
테스트 사진 1장: `(주)경북환경_벽돌 성형기 주변 계단 상부 추락 위험.jpg` (gold 제43조 y; 실제 위반 = ㉠벽·설비 사이 깊은 개구부 ㉡고정식 사다리 ㉢폐기물 적치).

⚠ **전부 사진 1장 실측** — 경향이지 통계 아님. 채택 전 10~20장 확대 실측 필요.

## 실측 1 — 열린 탐색(open-ended), 6개 모델

같은 프롬프트("위반을 찾고 0~1000 정규화 b-box 반환"), 이미지 1600px 축소(입력 ~2.5k 토큰).

| 모델 | 검출 | 개구부(핵심 gold) | 특징 |
|---|---|---|---|
| gpt-4.1(현행 Vision) | 3 | 말만, 박스 엉뚱 | 경계 느슨·사다리 누락 |
| gpt-5.4 | 4 | ✗(통짜 박스) | 거침 |
| **gpt-5.5** | 5 | **✓ 유일 정확** | 난간 빈 틈·물뿌리개 |
| 5.6-luna | 4 | ✗(가장자리만) | 균형 |
| 5.6-sol | 5 | ✗(가장자리만) | 최다·최세밀(벽면 폼타이 앵커까지) |
| 5.6-terra | 3 | **✗ 완전 누락** | 박스 최정밀이나 저재현 |

핵심 관찰: **"박스가 정밀한 모델" ≠ "정답 위반을 찾는 모델"**(terra는 물뿌리개를 핀포인트하면서 gold 위반을 통째 누락). 그리고 **6/6 모두 사다리 구조 위반(제24조)을 스스로는 못 잡음** → "무엇이 위반인가"는 모델이 아니라 지식층(cue-pool·판단기준)의 몫임이 재확인.

## 실측 2 — reasoning effort (gpt-5.5)

기존 프로브는 effort 미지정 = **기본 medium**. 실측(입력 2,502 고정):

| effort | 출력(그중 reasoning) | 관찰 |
|---|---|---|
| low | 264 (0) | 유일하게 사다리 출입부 포착(n=1 주의) |
| medium | 949 (645) | 개구부 ✓ |
| high | 2,747 (2,433) | 개구부 ✓ + 벽면 앵커 |

→ reasoning을 늘려도 b-box 품질이 선형 개선되지 않음. targeted 용도는 low~medium이면 충분해 보임.

## 실측 3 — SSOT 주입 방식 비교 (luna·terra)

- **SSOT 전체** = 43,328자 ≈ 29~36k 토큰/장(입력 13~15배) — 시도 안 함. arm C 실측(프롬프트 지식주입 순이득 ≈0)으로 기각.
- **구조도 체크리스트만**(+480토큰, 시설→조문 목록 "하나씩 확인하라"): **실패.** luna 1건(폐기물만)·terra 2건(폐기물+발끝막이판 제13조). 개구부·사다리 둘 다 누락. 체크리스트가 오히려 보수화(luna 4→1건). **지식을 프롬프트로 줘도 '판단'은 안 좋아진다 — arm C 패턴 3번째 재현.**
- **targeted grounding**("감독관이 확정한 위반 3건[제43·24·4조], 판단 말고 **위치만**"): **성공.**

| 모델 | targeted 결과 | 출력(reasoning) |
|---|---|---|
| 5.6-terra | 3/3 최정밀(개구부 피트 타이트) | 403 (204) |
| 5.6-luna | 3/3(박스 다소 넓음) | 585 (380) |
| **gpt-5.5(정식)** | **3/3 정확** | 722 (512) |

## 결론·권고 (재논의용)

1. **서비스 아키텍처**: `기존 파이프라인(cue→조문 확정) → b-box 호출("확정 위반 위치만") → 오버레이`. 판단=지식층, 위치=모델.
2. **모델**: 설정값으로(`BBOX_MODEL`) — 현 정식 최상위 gpt-5.5. 프리뷰(luna/sol/terra)는 하드코딩 금지(코드네임 소멸 리스크), 5.6 정식 출시 시 설정 교체. terra급 정밀이 정식으로 오면 최적.
3. **비용**: 장당 입력 ~2.6k + 출력 0.4~0.7k ≈ 요청당 1회 추가 호출. 부담 없음.
4. **강건성**: b-box 실패 시 박스만 생략(조문·설명·벌칙 정상) — 우아한 강등.
5. **하지 말 것**: SSOT 전체/구조도 프롬프트 주입으로 '찾게' 하기(실측 실패), 프리뷰 모델 고정, 사진 1장 결과로 채택 확정.
6. **채택 전 필요**: 10~20장 확대 실측(박스 IoU/적중률 통계). **2차 검수 결과 수령 후 재논의(보류 중)**.
